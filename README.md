# Codebase Q&A Service

AI-powered codebase Q&A service using GitHub Copilot SDK. Team members authenticate with GitHub and use their own Copilot license to ask questions about codebases.

## Architecture

```
Team Members → GitHub OAuth → App (Express + Copilot SDK + Next.js) → AI Agents → Answers
```

The application runs as **one Node.js process**: Express handles `/api/*` and `/health`, and Next.js serves the UI and static assets on the same port (default **3000**).

### Features

- 🔐 **GitHub OAuth** - Each user uses their own Copilot license
- 🤖 **3 AI Agents** - Explorer, Analyzer, Architect (specialized for different tasks)
- 💬 **Real-time Streaming** - Live agent activity and responses
- 📚 **Multi-Repository** - Support for multiple codebases
- 🐳 **Docker Deploy** - Single container
- 💾 **Session Persistence** - Maintains context across questions

## Prerequisites

1. **GitHub Copilot License** - Each team member needs active Copilot subscription
2. **GitHub OAuth App** - For authentication
3. **Container Runtime** - One of:
   - **Docker + Docker Compose**
   - **Podman + podman-compose** (supported on Windows/Linux)

### Podman Notes (Windows)

- This project supports Podman, including `podman-compose`.
- If you use Podman, use `podman-compose` commands instead of `docker-compose`.
- The compose file builds from the repository root (`context: .`) using the root `Dockerfile`.

## Setup

### Step 1: Create GitHub OAuth App

1. Go to: https://github.com/settings/developers
2. Click "New OAuth App"
3. Fill in:
   - **Application name**: `Codebase Q&A Service`
   - **Homepage URL**: `http://localhost:3000`
   - **Authorization callback URL**: `http://localhost:3000/api/auth/callback`
4. Click "Register application"
5. Generate a new client secret
6. Save your **Client ID** and **Client Secret**

### Step 2: Configure Environment

```bash
# Copy example env file
cp .env.example .env

# Edit .env and add your GitHub OAuth credentials
# GITHUB_CLIENT_ID=your_client_id_here
# GITHUB_CLIENT_SECRET=your_client_secret_here
# SESSION_SECRET will be auto-generated by setup.sh
```

### Step 3: Build and Run (Docker)

```bash
# Run setup script (creates .env with random session secret)
chmod +x setup.sh
./setup.sh

# Build container
# Docker:
docker-compose build
# Podman:
podman-compose build

# Start service
# Docker:
docker-compose up -d
# Podman:
podman-compose up -d

# Check logs
# Docker:
docker-compose logs -f
# Podman:
podman-compose logs -f
```

### Step 4: Access the Application

Open your browser to: **http://localhost:3000**

## Repositories

Cloned repositories are stored under **`~/.copilot-sdk-demo/repos`** on the machine (or container user home). Add them from the UI with **Clone repository**; they are not kept in a `./repos` folder in this project.

## Docker

A single **app** service exposes port **3000** (Express + Next.js). Health checks use `http://localhost:3000/health`. A named volume persists clones at `/root/.copilot-sdk-demo/repos` inside the container.

## Environment Variables

See `.env.example` for the full list. Common values:

```bash
# GitHub OAuth
GITHUB_CLIENT_ID=your_oauth_app_client_id
GITHUB_CLIENT_SECRET=your_oauth_app_client_secret

# Session
SESSION_SECRET=random_64_char_string

# Server
NODE_ENV=production
PORT=3000
BASE_URL=http://localhost:3000
```

Optional: `FRONTEND_URL`, `GITHUB_OAUTH_BASE_URL`, `GITHUB_API_BASE_URL`, `COPILOT_MODEL`, `SESSION_COOKIE_SECURE` (see `.env.example` comments).

## Troubleshooting

### OAuth callback fails
**Solution:** Verify callback URL in GitHub OAuth app matches: `http://localhost:3000/api/auth/callback`

### No repositories shown
**Solution:** Clone at least one repository from the app UI, or confirm `~/.copilot-sdk-demo/repos` (or the Docker volume) is writable and contains git checkouts.

### Copilot SDK errors
**Solution:** Ensure user has active GitHub Copilot license. Check logs: `docker-compose logs -f app`

### Podman build error: "no Containerfile or Dockerfile specified or found in context directory"
**Solution:** Run `podman-compose build` from the repository root where `docker-compose.yml` and `Dockerfile` live.

### Port already in use
**Solution:** Stop existing services on port 3000 or change `PORT` in `.env` and the host mapping in `docker-compose.yml`

## Architecture Decisions

### Why GitHub OAuth?
- Each user uses their own Copilot license
- No shared API keys needed
- Proper access control

### Why Docker?
- Easy deployment
- Isolated environment
- Consistent across team

### Why SSE (Server-Sent Events)?
- Real-time streaming responses
- Simpler than WebSockets
- Works with HTTP/2

### Why one process?
- Simpler deployment and configuration
- Same-origin `/api/*` without a separate backend URL
